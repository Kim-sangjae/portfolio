CSORA – CS 지식 학습 플랫폼

컴퓨터공학(CS) 지식을 단순 암기가 아니라 "문제 풀기 → 틀린 문제 다시 풀기 → 실력 확인" 과정을 반복하며 익힐 수 있도록 만든 웹 서비스입니다. 자료구조·알고리즘·운영체제·네트워크·데이터베이스 등 7개 분야, 1,500개 이상의 문제를 제공하며 csora.co.kr에서 실제로 운영 중입니다. 기획부터 설계·개발·배포·운영까지 혼자 진행했고, AI 코딩 도구인 Claude Code를 함께 활용해 개발 속도를 높였습니다.

주요 기능

학습

  • 카테고리별 랜덤 퀴즈 (최근 3세션 문제 자동 제외로 다양성 확보)
  • 오답 복습 스케줄링 — 에빙하우스 망각곡선 기반 1·3·7·30일 간격 재출제
  • 시간제한 모드(문제당 15초), 오늘의 문제(매일 00시 갱신 · 전체 참여자 정답률 공개)

대결 & 친구

  • 친구와 실시간으로 겨루는 1:1 퀴즈 대결 (10문제, 문제당 20초 제한)
  • 친구 추가 · 대결 초대 · 지금 접속 중인지 실시간으로 확인
  • 친구와 나누는 1:1 채팅 (대화 내용은 저장하지 않고, 로그아웃하면 사라짐)
  • 대결 누적 승/무/패 기록, 친구 목록에 결과 실시간 반영

성장 추적

  • 유저 레벨(XP, 최대 200레벨) · 카테고리별 단계 · 정답률 등급(브론즈/실버/골드)
  • 연속 출석 스트릭, 뱃지·업적 30종, 주간 목표 달성 포인트
  • 마이페이지 카테고리별 오답 상세 분석, 문제 북마크

커뮤니티 & 운영

  • 문제 제보 게시판(좋아요·신고 가능) — AI로 비슷한 문제를 미리 찾아내 중복 등록 방지
  • 문제 등록 시 AI(OpenAI)가 오답 보기와 해설을 자동으로 생성 — 내가 쓴 정답은 그대로 두고 빈 부분만 채움 (1인당 하루 20회 제한)
  • 카카오톡으로 결과 공유, 댓글·대결 실시간 알림, PC 알림, 앱처럼 설치해 쓰는 PWA
  • 관리자 기능: 문제 승인/거절, AI로 카테고리·난이도별 문제를 한 번에 대량 생성(최대 50개), 부적절한 닉네임·욕설 자동 필터링, 이용 현황 통계 대시보드
  • 검색엔진에 잘 노출되도록 사이트맵·구조화 데이터 적용, 구글·네이버 검색엔진 등록

설계 포인트

  • 퀴즈 정답은 서버에서만 확인할 수 있도록 만들어, 화면 코드를 들여다봐도 정답이 보이지 않게 처리
  • 별도의 캐시 서버 없이 데이터베이스만으로 짧은 시간에 반복되는 요청을 막는 장치를 마련해 스팸·부정 사용 방지
  • 회원 탈퇴 시 그 회원과 연결된 기록(풀이 내역·알림·대결방 등)을 먼저 정리한 뒤 계정을 삭제해 데이터가 꼬이지 않도록 처리
  • 정보를 바꾸는 모든 요청은 서버에서 권한을 다시 한번 확인 — 화면에서 버튼을 숨기는 것만으로는 보안이라 보지 않음
  • 매일·매주 초기화되는 기능은 한국 시간 기준으로 처리해, 세계 표준시로 계산할 때 생기는 새벽 시간대 오류 방지
  • 문제를 무작위로 섞을 때 한쪽으로 쏠리지 않도록 검증된 셔플 방식(Fisher-Yates) 사용
  • 데이터가 많은 목록은 한 번에 다 불러오지 않고 나눠서 불러오도록 처리, 여러 명이 동시에 제출해도 통계가 꼬이지 않도록 처리
  • AI가 만든 문제도 저장하기 전에 기존 문제와 얼마나 비슷한지 자동으로 검사해서, 너무 비슷하면 저장하지 않고 걸러냄
  • 문제를 대량으로 만들 때와 오답만 살짝 채울 때 서로 다른 AI 모델을 사용해 속도와 비용의 균형을 맞춤

Review

혼자서 기획부터 배포·운영까지 끝까지 끌고 간 첫 개인 프로젝트입니다. Claude Code를 함께 활용하면서도 구조 설계·보안·데이터 정합성 같은 핵심 결정은 직접 검토하고 책임지는 방식으로 진행했습니다. 1,500개 이상의 문제 데이터와 실시간 대결, 레벨/뱃지 같은 성장 시스템까지 기능이 계속 늘어나면서, 프로젝트를 18단계로 나눠 단계별로 안정화하며 확장하는 방식의 중요성을 체감했습니다. 현재도 실사용자를 대상으로 배포·운영 중이며, 계속 기능을 추가하고 있습니다.

개발 중 이슈

1:1 대결 기능에서는 두 사람의 화면이 항상 같은 문제, 같은 타이밍으로 맞춰져야 했습니다. 실시간 연결을 처음부터 직접 구현하는 대신, 실시간 데이터 동기화 서비스(Supabase Realtime)를 이용해 양쪽 화면이 서로의 상태를 실시간으로 주고받도록 구성했습니다. 인터넷 연결이 잠깐 불안정해지는 경우를 대비해 1초·0.5초 간격으로 상태를 다시 확인하는 보조 장치도 함께 넣어서 화면이 어긋나는 문제를 최소화했습니다. 또 한쪽이 문제를 계속 건너뛰는 걸 막기 위해, 양쪽이 연속으로 건너뛰면 제한 시간을 줄이고 두 번 연속되면 그 문제를 무효 처리하는 규칙도 추가했습니다.
사용자가 게시판에 새 문제를 등록할 때, 기존 1,500개 넘는 문제와 표현만 다르고 내용은 같은 문제가 계속 쌓이는 게 문제였습니다. 단순히 글자가 똑같은지만 비교해서는 표현이 조금만 달라도 같은 문제인 걸 걸러내지 못했습니다. 그래서 문장의 의미가 얼마나 비슷한지 비교하는 방식과 글자 조합이 얼마나 겹치는지 비교하는 방식을 함께 사용해 유사한 문제를 찾아내도록 했습니다. 문제를 등록하는 시점에 비슷한 문제를 먼저 보여주고, 관리자가 같은 뜻으로 쓰이는 단어들을 직접 등록·관리할 수 있게 해서 중복 등록을 크게 줄였습니다.
개인 프로젝트 규모에서는 별도의 캐시 서버(Redis) 같은 인프라를 추가로 두기보다, 이미 쓰고 있는 데이터베이스만으로 스팸과 부정 사용을 막을 방법이 필요했습니다. 댓글·신고·문의·채팅에는 짧은 시간에 반복 요청이 오면 막는 장치를 데이터베이스 기반으로 적용했고, 퀴즈 정답은 서버에서 채점할 때만 확인할 수 있도록 해서 화면 코드를 봐도 정답이 보이지 않게 했습니다. 같은 문제를 반복 제출해서 보상을 여러 번 받는 것도 막았고, 친구와의 대결도 하루에 만들 수 있는 횟수를 제한해서 가짜 계정으로 경험치를 부풀리는 것을 방지했습니다. 별도 인프라를 추가하지 않고도 실제 서비스 수준의 부정 사용 방지가 가능하다는 것을 확인할 수 있었습니다.
문제 데이터를 1,500개 이상 확보하고 계속 늘려가야 해서, OpenAI의 AI 모델을 두 가지 용도로 나눠서 붙였습니다. 관리자만 쓸 수 있는 대량 생성 기능은 성능이 더 좋은 모델(GPT-4o)을 사용해 카테고리·난이도별로 한 번에 최대 50개까지 문제를 만듭니다. 답변은 항상 정해진 형식으로만 오도록 강제하고, 직전에 만든 문제와 겹치지 않도록 이전 목록도 함께 전달합니다. 만들어진 문제는 바로 저장하지 않고, 기존 문제들과 얼마나 비슷한지 자동으로 검사해서 너무 비슷하면 저장 전에 걸러냅니다. 사용자가 직접 게시판에 문제를 등록할 때는 좀 더 가볍고 저렴한 모델(GPT-4o-mini)을 붙여서, 오답 보기 3개와 해설만 대신 만들어주는 기능을 넣었습니다. 사용자가 이미 써놓은 정답이나 오답은 그대로 두고 비어 있는 부분만 채워주는 방식이라, 사용자가 직접 입력한 내용을 덮어쓰지 않도록 신경 썼습니다. 아무 제한 없이 쓸 수 있게 하면 비용이 계속 늘어나기 때문에 하루 20회로 사용 횟수를 제한했습니다. 대량으로 문제를 만들 때와, 이미 있는 문제에 살짝 살을 붙일 때는 필요한 품질과 비용이 서로 달라서, 처음부터 상황에 맞게 다른 모델을 골라 쓰도록 설계했습니다.
