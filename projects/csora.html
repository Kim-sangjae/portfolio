CSORA – CS 지식 학습 플랫폼

CS 지식을 단순 암기가 아닌 문제 풀이 → 오답 복습 → 실력 확인 사이클로 습득할 수 있도록 설계한 웹 서비스입니다. 자료구조·알고리즘·OS·네트워크·DB·컴퓨터구조·소프트웨어공학 7개 영역, 1,500개 이상의 문제를 제공하며 csora.co.kr에서 실서비스 중입니다. 기획부터 설계·개발·배포·운영까지 혼자 진행했고, Claude Code를 AI 페어 프로그래머로 활용해 개발 속도를 높였습니다.

  • 친구 추가 · 대결 초대 · 실시간 접속 상태 확인

  • 연속 출석 스트릭, 뱃지·업적 30종, 주간 목표 달성 포인트

커뮤니티 & 운영

  • 문제 제보 게시판(좋아요·신고) — 유사 문제 하이브리드 검색(벡터+pg_trgm)으로 중복 등록 방지
  • 문제 등록 시 OpenAI(GPT-4o-mini)로 오답 보기·해설 자동 생성 — 사용자가 작성한 정답은 그대로 두고 빈 항목만 채움 (1인당 1일 20회 제한)
  • 카카오톡 결과 공유, 댓글/대결 실시간 알림, PC 데스크톱 알림, PWA
  • 관리자: 문제 승인/거절/블라인드, OpenAI(GPT-4o) 기반 카테고리·난이도별 문제 배치 생성(최대 50개), 닉네임·욕설 필터링, 애널리틱스 대시보드
  • SEO(sitemap·구조화 데이터), 구글 서치콘솔·네이버 서치어드바이저 등록

설계 포인트

  • 정답 필드는 서버에서만 접근하도록 분리해 클라이언트에 노출되지 않도록 처리
  • Redis 없이 DB 테이블 기반 레이트리밋으로 스팸·파밍·스크래핑 방지
  • 계정 완전삭제 시 FK RESTRICT로 얽힌 참조(풀이기록·알림·대결방 등)를 트랜잭션으로 먼저 정리 후 삭제
  • 모든 상태 변경 API에 소유권·권한을 서버에서 재검증 (클라이언트 UI 숨김은 보안으로 취급하지 않음)
  • 일간·주간 초기화는 UTC가 아닌 KST 기준으로 처리해 새벽 시간대 리셋 오류 방지
  • Fisher-Yates 셔플로 문제 순서 편향 제거 (Array.sort(Math.random) 대비)
  • 대규모 목록 조회는 서버사이드 페이지네이션 적용, 동시 제출 통계는 Prisma 트랜잭션으로 정합성 보장
  • AI가 생성한 문제도 임베딩 유사도(pgvector, 0.85 이상)를 검사해 기존 문제와 겹치면 저장 전에 자동 스킵
  • 대량 생성(GPT-4o)과 오답/해설 자동완성(GPT-4o-mini)에 모델을 구분 사용해 응답 속도·비용 최적화

Review

혼자서 기획부터 배포·운영까지 끝까지 끌고 간 첫 개인 프로젝트입니다. Claude Code를 페어 프로그래머로 활용하면서도 아키텍처·보안·데이터 정합성 같은 핵심 결정은 직접 검토하고 책임지는 방식으로 진행했습니다. 1,500개 이상의 문제 데이터와 실시간 대결, 레벨/뱃지 같은 성장 시스템까지 기능이 계속 늘어나면서, 프로젝트를 18단계로 나눠 단계별로 안정화하며 확장하는 방식의 중요성을 체감했습니다. 현재도 실사용자를 대상으로 배포·운영 중이며, 계속 기능을 추가하고 있습니다.

개발 중 이슈

1:1 대결 기능에서 양쪽 클라이언트의 문제 진행 상태를 실시간으로 맞춰야 했습니다. WebSocket을 직접 관리하는 대신 Supabase Realtime Broadcast로 채널 기반 양방향 동기화를 구성했고, 연결이 지연되는 경우를 대비해 1초/500ms 간격의 폴링 fallback을 함께 두어 접속 환경에 따른 싱크 오차를 최소화했습니다. 연속 쌍방 스킵 시 타이머를 단축하고, 2회 연속 발생하면 무효 처리하는 규칙을 추가해 어뷰징성 스킵도 함께 방지했습니다.
사용자가 게시판에 새 문제를 등록할 때 기존 1,500개 이상의 문제와 겹치는 문제가 계속 쌓이는 문제가 있었습니다. 단순 텍스트 일치 검사로는 표현만 다른 유사 문제를 걸러내지 못했습니다. 벡터 유사도, pg_trgm(트라이그램) 유사도, 희귀 토큰 가중치를 함께 사용하는 하이브리드 재정렬 방식을 적용해 등록 시점에 유사 문제를 찾아 보여주고, 관리자가 동의어 그룹을 직접 추가·관리할 수 있도록 하여 중복 등록을 크게 줄였습니다.
개인 프로젝트 규모상 Redis 같은 별도 인프라를 두기보다 Postgres만으로 스팸·파밍을 막을 방법이 필요했습니다. 댓글·신고·문의·채팅에는 DB 테이블 기반 레이트리밋을 적용했고, 퀴즈 정답은 서버 채점 시점에만 접근하도록 하여 플레이 화면에 정답이 노출되지 않게 했습니다. 세션 재제출 레이트리밋으로 보상 파밍을, 대결 생성은 친구쌍 단위 일일 상한을 두어 알트 계정을 통한 XP 파밍을 방지했습니다. 외부 인프라를 추가하지 않고도 실서비스 수준의 남용 방지가 가능하다는 것을 확인할 수 있었습니다.
문제 데이터를 1,500개 이상 확보하고 계속 늘려가야 해서, OpenAI API를 두 가지 용도로 나눠 붙였습니다. 관리자 전용 대량 생성은 gpt-4o를 사용해 카테고리·난이도별로 최대 50개씩 배치 생성합니다. JSON 형식으로만 응답하도록 강제하고, 직전 생성분과 중복되지 않도록 프롬프트에 제외 목록을 같이 넣습니다. 생성된 문제는 그대로 저장하지 않고 pgvector 임베딩 유사도가 0.85 이상이면 기존 문제와 겹친다고 보고 저장 전에 걸러냅니다. 사용자가 게시판에 문제를 등록할 때는 gpt-4o-mini로 오답 보기 3개와 해설만 가볍게 채워주는 기능을 붙였습니다. 이건 사용자가 직접 쓴 정답과 일부 오답은 그대로 두고 빈 항목만 채우는 방식이라, 사용자의 원래 입력을 덮어쓰지 않도록 신경 썼습니다. 무제한으로 호출되면 비용이 늘어나기 때문에 하루 20회로 제한을 걸었습니다. 대량 생성과 부분 자동완성은 요구되는 품질과 비용이 달라서 처음부터 모델을 gpt-4o / gpt-4o-mini로 구분해서 썼습니다.
